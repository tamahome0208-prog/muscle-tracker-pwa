# 筋トレ管理 PWA

JOYFIT24 室蘭モルエ中島のマシンで回す週3プログラム（A: 胸・肩・三頭 / B: 背中・二頭 / C: 脚・腹）の記録アプリ。

開いたら今日やることが出ていて、✓を押すだけで記録が終わることを最優先に作っています。

## 使い方

1. Android Chrome で公開URLを開く
2. メニュー →「ホーム画面に追加」で PWA としてインストール
3. 設定タブで Gemini API キーを登録すると、食事写真・レシート・インボディ結果紙の読み取りが使えます（任意）

## 主な機能

| タブ | 内容 |
|---|---|
| 🏠 ホーム | 今日やること・死守2項目のバー・連続週数・クイック記録 |
| 💪 トレ | 前回値プリセット済みの✓タップ記録・90秒タイマー・自己ベスト演出 |
| 🍽 食事 | ワンタップ登録・バーコード・写真/レシートOCR |
| 📷 写真 | 前回写真を重ねた撮影ガイド・before/after比較スライダー |
| 📈 記録 | 週次総挙上量・体組成3本重ね・部位レーダー・カレンダー・称号 |
| ⚙️ 設定 | 目標値・APIキー・バックアップ |

### 設計上の判断

- **ローテーションは曜日固定にしない。** A→B→C の順送りなので、1回サボっても崩れません。
- **カロリーは下限側を守る。** 1,500kcal を下回った日は警告を出します。摂取を削るほど筋肉が落ちて目的から遠ざかるため、上限超過より下限割れを重く扱います。
- **総挙上量が主指標。** 体重が横ばいでも週ごとに動くので、変化が見えます。
- **最初の4週間は2項目だけ評価。** 週3ジムと朝プロテインが習慣になれば、あとは続きます。

## 開発

```bash
npm test                      # ロジック層のテスト（103件）
```

ローカル確認は任意の静的サーバーで。Service Worker とカメラは `http://localhost` か HTTPS が必要です。

ビルド工程はありません。`index.html` から ES modules を直接読み込み、Chart.js は `vendor/` に同梱してオフラインでも動くようにしています。

### テストの方針

`js/store.js` / `workout.js` / `nutrition.js` / `game.js` / `body.js` は DOM とネットワークに触らない純粋関数として切り出し、Node の `node:test` でテストしています。UI・IndexedDB・外部APIは自動テスト対象外です。

テストを追加するときは、**実装を意図的に壊してテストが落ちることを確認**してください。このプロジェクトでは「通っているが何も保証していないテスト」が12件見つかっています（例: `set()` から永続化処理を消しても全件パスする状態でした）。

## データの扱い

- 記録データは端末の localStorage、体の写真は IndexedDB に保存されます。サーバーには送信しません
- Gemini API に送るのは食事写真・レシート画像・インボディ結果紙のみ
- Open Food Facts に送るのは JAN コード13桁のみ（設定でオフにできます）
- **体の写真は端末外に出ません。** `js/photos.js` と `js/photoTab.js` には外部通信APIが1つも含まれておらず、送信経路が構造的に存在しません
- バックアップは設定タブから JSON でエクスポートします。API キーは意図的に含めません（端末外に持ち出されやすいファイルのため）
