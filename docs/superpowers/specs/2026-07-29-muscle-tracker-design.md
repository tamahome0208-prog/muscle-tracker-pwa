# 筋トレ継続管理アプリ 設計書

作成日: 2026-07-29

## 1. 目的

筋トレを1年単位で継続するための管理アプリ。既存の会話で確定した「JOYFIT24 室蘭モルエ中島のマシンだけで回す週3プログラム」と「タンパク質100g / 1,700〜1,800kcal の死守」を、記録の手間ゼロで回し続けられるようにする。

### コンセプト

**「開いたら今日やることが出ている。✓を押すだけで記録が終わる」**

継続の最大の敵は入力の手間。写真AIより先に「打たなくていい設計」を土台に置く。

### 利用者プロフィール（初期値として埋め込む）

| 項目 | 値 |
|---|---|
| 身長 | 162cm |
| 体重 | 60kg（横ばい維持が目標） |
| ジム | JOYFIT24 室蘭モルエ中島 |
| 併走運動 | バドミントン 週2回 × 1時間 |
| 目標 | 3ヶ月で筋肉+2〜3kg / 体脂肪-3%、体重は58〜60kgのまま |

### 死守する2項目

1. **タンパク質 100〜120g/日**
2. **1,700〜1,800 kcal/日**（下限を守ることを重視。1,500未満は警告）

発泡酒500ml/日（約150kcal・純アルコール20g）は許容。トレ日は食後に飲む運用。

## 2. 技術構成

- 単一ページ + **ES modules による分割**（ビルド不要）
- **localStorage**（記録データ） + **IndexedDB**（体の写真のみ）
- **Chart.js**（グラフ）
- **PWA**（Service Worker で完全オフライン動作）
- デプロイ: **GitHub Pages**
- 対象端末: **Android（Chrome）**

既存の `slot-dashboard-pwa` と同じデプロイ方式だが、機能数が多いため単一HTMLではなくモジュール分割とする。

### ディレクトリ構成

```
index.html
manifest.json
sw.js
css/style.css
js/
  main.js        エントリポイント・初期化
  store.js       localStorage の読み書き（他モジュールは直接触らない）
  photos.js      IndexedDB（体の写真）専用。外部通信を一切持たない
  workout.js     ローテーション判定・セット記録・PB判定・総挙上量（純粋関数中心）
  nutrition.js   食事集計・達成率・下限警告（純粋関数中心）
  body.js        体重・体組成
  ocr.js         Gemini API 呼び出しとフォールバック。体写真は通さない
  barcode.js     BarcodeDetector + Open Food Facts 照会
  game.js        XP/レベル/ストリーク/称号（純粋関数のみ）
  charts.js      Chart.js 描画
  ui.js          タブ切替・DOM 操作
data/
  exercises.json JOYFIT室蘭モルエ中島のマシン一覧とプログラムA/B/C
  foods.json     初期のよく食べる食品
test/
  *.test.js      node:test による純粋関数テスト
docs/superpowers/specs/
```

### モジュール境界の原則

- `store.js` 以外は localStorage に直接アクセスしない
- `photos.js` は IndexedDB 専用。**fetch を一切含まない**（体写真の外部送信を構造的に不可能にする）
- `game.js` `workout.js` `nutrition.js` は DOM に触らない純粋関数のみ。テスト対象
- `ui.js` `charts.js` は計算しない。表示のみ

## 3. データモデル（localStorage）

すべて `mt.` プレフィックス。

```js
mt.profile = {
  height: 162,
  startDate: "2026-07-29",
  targets: { protein: 100, kcalMin: 1700, kcalMax: 1800, kcalFloor: 1500, alcoholMl: 500 }
}

mt.workouts = [{
  id, date, program: "A"|"B"|"C",
  sets: [{ exId, weight, reps }],
  volume,            // Σ(weight × reps)。保存時に計算
  durationMin, memo
}]

mt.exercises = [{ id, name, program, part, defaultWeight, defaultReps, sets, note }]

mt.meals = [{
  id, datetime,
  items: [{ name, kcal, protein, grams }],
  source: "tap"|"barcode"|"photo"|"receipt"|"manual"
}]

mt.foods = [{ id, name, unit, kcal, protein, jan?, useCount }]   // 使うほど育つマイメニュー

mt.body = [{ date, weight, muscle, fatPct, source: "inbody"|"scale" }]

mt.badminton = [{ date, durationMin }]

mt.game = {
  xp: { chest, back, shoulder, leg, arm, abs },
  streakWeeks, lastWeekKey,
  bests: { [exId]: { weight, reps, date } },
  badges: [badgeId]
}

mt.settings = { geminiKey, useOpenFoodFacts: true, photoReminder: true }

mt.schemaVersion = 1
```

体の写真は localStorage に置かない（容量5MBで他の記録ごと壊れるため）。IndexedDB `mt-photos` ストアに分離する。

```js
// IndexedDB: mt-photos
{ id, date, angle: "front"|"side"|"back", blob, width, height }
```

## 4. トレーニングプログラム

JOYFIT24 室蘭モルエ中島の設置マシンのみで構成。通常のチェストプレスマシンが無いため、胸はインクラインチェストプレス（プレートロード式）が主軸。

各種目 3セット × 8〜12回 / インターバル90秒 / 最後の2回がキツい重量。

### A：胸・肩・三頭

| 種目 | 初期重量 | 部位 |
|---|---|---|
| インクラインチェストプレス | 片側5〜10kg | 胸 |
| ペックフライ（胸側） | 20〜25kg | 胸 |
| ショルダープレス | 15〜20kg | 肩 |
| ラテラルレイズ | 5〜10kg | 肩 |
| トライセップエクステンション | 15〜20kg | 腕 |
| ディプアシスト | 補助重め | 胸・腕 |

### B：背中・二頭

| 種目 | 初期重量 | 部位 |
|---|---|---|
| ラットプルダウン | 30〜35kg | 背中 |
| シーテッドロー | 30〜35kg | 背中 |
| プルダウン | 30kg | 背中 |
| リアデルト | 15〜20kg | 肩 |
| バイセップスカール | 15〜20kg | 腕 |
| チンアシスト | 8回×3目標 | 背中 |

### C：脚・腹

| 種目 | 初期重量 | 部位 |
|---|---|---|
| レッグプレス | 60〜80kg | 脚 |
| レッグエクステンション | 25〜30kg | 脚 |
| シーテッドレッグカール | 20〜25kg | 脚 |
| バックエクステンション | 自重〜10kg | 背中 |
| アブコースター | 15回×3 | 腹 |
| アブドミナル | 20〜30kg | 腹 |

### ローテーションは曜日固定にしない

理想形は「月A・火バド・水B・木休・金C・土バド・日休」だが、曜日固定は1回サボった時点で破綻する。**A→B→C→A の順送り**で管理し、アプリが「次はB」と提示する。

例外として、**脚の日（C）の翌日にバドミントンの記録が入ろうとした場合のみ警告を出す**（回復が間に合わないため）。

## 6. トレーニング記録UI（手間ゼロの本丸）

```
【B】背中・二頭                          ⏱ 90秒
─────────────────────────────
ラットプルダウン    35kg × 10    [✓][✓][ ]   前回 35×10
シーテッドロー      35kg × 10    [ ][ ][ ]   前回 32.5×12  ⚡
プルダウン          30kg × 12    [ ][ ][ ]
```

- 種目と重量は**前回の記録がプリセット済み**。数字入力は不要
- **✓を1回押す = 1セット完了**
- 重量変更は `＋/−`（2.5kg刻み）、回数は1刻み
- ✓を押した瞬間に**90秒タイマー自動起動**、終了時にバイブ
- ⚡ = 「前回より1回でも多く挙げれば自己ベスト」の予告
- PB更新時にエフェクト＋XP加算＋履歴に記録

初回起動時は §4 の初期重量を使う。

## 7. 食事記録（3段構え）

夜1食＋朝プロテインという食生活はリピート品が大半のため、ワンタップで8割を処理する。

### ① ワンタップ

ホーム下部に常時ボタン。押すだけで加算。**使用回数の多い順に自動で並び替わる**。

初期セット: プロテイン1杯 / ゆで卵 / サラダチキン / おにぎり / 発泡酒500ml / 唐揚げ / ごはん150g

### ② バーコード

Android Chrome ネイティブの `BarcodeDetector` を使用（ライブラリ不要）。

1. JAN読み取り → ローカル `mt.foods` を照合
2. 無ければ **Open Food Facts**（無料オープンDB）に問い合わせ
3. それでも無ければ1回だけ手入力 → 次回から自動登録

Open Food Facts に送るのは**JANコード13桁のみ**。設定で無効化可能。

### ③ 写真 / レシート OCR（Gemini API）

①②で拾えないとき（外食・自炊）のみ使用。

- **食事写真** → 料理名・kcal・タンパク質を推定 → **確認画面で修正してから保存**
- **レシート** → 品目を一括抽出 → 不要品目のチェックを外して除外 → まとめて登録
- **画像は保存しない**。抽出後のテキスト結果のみ localStorage に残す

### カロリー下限警告

1,500kcal を下回った日は警告を出す。会話の経緯（1,200 → 1,000kcal と数字が下がり続けた）を踏まえ、**上限超過より下限割れを重く扱う**。1,000kcal 台は筋肉が削れる領域であり、目的と逆行する。

## 8. 体組成

- 月1のインボディは**体重・筋肉量・体脂肪率の3項目のみ**手入力。結果紙の写真OCRにも対応
- 体重は任意頻度。催促しない
- グラフは体重・筋肉量・体脂肪率の**3本重ね**（体重横ばいのまま中身が変わる推移を可視化）

## 9. 体の写真記録

### 保存

- IndexedDB `mt-photos` に保存（localStorage には置かない）
- 保存時に長辺1080pxへリサイズ + JPEG圧縮（1枚 約200KB）
- 月4枚 × 3アングル × 1年 ≒ 約30MB

### 撮影ガイド

進捗写真の失敗要因は「角度・距離・光がバラバラ」。対策として:

- **前回の同アングル写真を半透明で重ねて表示**しながら撮影
- アングルは **正面 / 横 / 背面** の3つに固定
- **週1（日曜）にリマインド**。毎日撮っても変化は見えない

### 比較ビュー

- **スライダーで before / after を重ねて比較**
- 「3ヶ月前と比較」「開始時と比較」をワンタップ切替
- 写真下にその時点の筋肉量・体脂肪率を併記
- 記録タブに月ごとのサムネイル・タイムライン

### プライバシー（厳格）

- **体の写真は外部送信しない**。`photos.js` は fetch を一切含まず、`ocr.js` を経由しない
- GitHub Pages に公開されるのはコードのみ。写真は端末内 IndexedDB のみ
- バックアップJSONに**デフォルトでは写真を含めない**。明示的に選択した場合のみ端末内にファイル保存
- サムネイルは写真タブ以外に表示しない（ジムで他タブを開いても見えない）

## 10. ゲーミフィケーション

### A：数字が伸びる快感

- **週次総挙上量の折れ線**を主指標に置く（体重計より確実に変化が見える）
- ホームに「**先週比 +320kg ↗**」を常時表示
- PB更新でエフェクト＋履歴記録

### B：部位レベル（RPG）

- 6部位（胸/背中/肩/脚/腕/腹）にレベル
- `部位XP += Σ(weight × reps) / 10`
- `level = floor(sqrt(XP / 100))`
- **固定式とし、チューニングしない**（バランス調整に時間を溶かさないため）
- **レーダーチャート**で弱点部位を可視化
- **称号**は会話で出た現実的な到達点に対応させる（「初心者ボーナス期」→「肩と胸に丸みが出た」→「腹筋上部が割れた」など）
- 月1インボディ入力を「ボス戦」として演出。3ヶ月前との差分を表示

### C：習慣ストリーク

- **連続週数**（その週にジム3回達成で1カウント）。日単位だと休養日で切れるため週単位
  - 連続週数の判定条件は**ジム3回のみ**。食事・写真は判定に含めない（条件を増やすと切れやすくなり、ストリークの意味が失われるため）
- **カレンダーヒートマップ**（💪ジム / 🏸バド / 📷写真 / 😴休養）。写真撮影はカレンダー表示のみ
- 死守2項目の日次達成率メーター
- 称号「定点観測」: 比較ビューを初めて開いたときに解放

### 初期4週間モード

会話の「まず1ヶ月、週3ジムと朝プロテインの2つだけ習慣化できれば、あとは自動的に進む」を反映。開始から4週間は **「週3ジム」と「朝プロテイン」の2つだけを評価対象**にする。他の指標は表示するが達成判定に含めない。

## 11. エラー処理

| 状況 | 挙動 |
|---|---|
| Gemini APIキー未設定 | 写真ボタンを無効表示＋設定への導線 |
| OCR失敗・タイムアウト | 即座に手入力フォームへフォールバック。**記録を落とさない** |
| オフライン | 全機能動作（OCRのみ不可）。Service Worker でキャッシュ |
| localStorage 破損 | 起動時に各キーを検証。壊れたキーだけ初期化し、他は保護 |
| IndexedDB 使用不可 | 写真タブのみ無効化。他機能は通常動作 |
| BarcodeDetector 非対応 | バーコードボタンを隠し、手入力に誘導 |

### バックアップ

設定タブから JSON エクスポート / インポート。機種変更・localStorage 消失に備える。写真はデフォルトで含めない。

## 12. テスト

Node 標準 `node:test` を使用（ブラウザ不要）。ES modules をそのまま import する。

| 対象 | 内容 |
|---|---|
| `workout.js` | ローテーション判定（A→B→C→A）、PB判定、総挙上量計算 |
| `nutrition.js` | 日次集計、達成率、下限警告の閾値 |
| `game.js` | XP計算、レベル計算、ストリーク判定、初期4週間モード |
| `store.js` | 破損データ検証・部分初期化 |

UI・ネットワーク・IndexedDB は自動テスト対象外（手動確認）。
